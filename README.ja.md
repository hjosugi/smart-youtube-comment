# スマートYouTubeコメントオーバーレイ

[![Chrome Web Store](https://img.shields.io/badge/Chrome%20Web%20Store-スマート%20YouTube%20コメントオーバーレイ-4285F4?logo=googlechrome&logoColor=white)](https://chromewebstore.google.com/detail/nkphcfhnfjceplpgcjccnpfdkheafohp)

NicoスタイルのYouTubeライブチャットオーバーレイのためのChrome MV3拡張機能です。メッセージをJavaScriptでローカルにスコアリングし、そのスコアを使用してコメントがビデオ上を速く、通常、または遅く移動するかを決定します。

目的は、有用なコメントを目立たせ、短い繰り返し反応、絵文字の洪水、または低価値のバーストが他のすべてを埋め尽くさないようにすることです。

## インストール

拡張機能はChrome ウェブストアで公開されています:

<https://chromewebstore.google.com/detail/nkphcfhnfjceplpgcjccnpfdkheafohp>

- 拡張機能ID: `nkphcfhnfjceplpgcjccnpfdkheafohp`
- ストアのカテゴリ: エンタテイメント
- リスティングの言語: 英語と日本語
- サポート・不具合報告: <https://github.com/hjosugi/smart-youtube-comment/issues>
- プライバシーポリシー: [docs/PRIVACY.ja.md](docs/PRIVACY.ja.md)

ストアのリスティングはChrome ウェブストアの審査を通過した最新バージョンを示すため、このリポジトリのバージョンより古い場合があります。最新のソースを試すには、[Chromeに読み込む](#chromeに読み込む)の手順で`extension/`を未パッケージのまま読み込んでください。

## ステータス

Chrome ウェブストアで公開済みです。実装済み:

- Chrome MV3拡張機能のスキャフォールド
- `web/`内のモバイルPWA
- `worker/`内のCloudflare Workerライブチャットリレー
- すべてのフレームからのYouTubeライブチャット抽出
- プレーヤー上の拡張ステージフレームで動く弾幕レンダラー。コメントはブラウザのコンポジターが動かします（既定）。極端に密なチャット向けに canvas レンダラーも選べます
- YouTube のトップページ、検索、チャンネルから開いた配信でも起動します（YouTube のページ内遷移に追従。読み込み直した視聴ページに限りません）
- コメントはライブ扱いです。タブが背面にある間、プレーヤーが画面外にある間、動画の一時停止中は溜め込まないので、戻ったときに大量に流れません
- コメントの右クリックメニュー: ピン留めとドラッグ、そのユーザーのコメントをまとめて非表示（NGリストに保存）
- プレーヤーに合わせた文字サイズ（「相対」モードでは全画面で拡大し、小さいウィンドウでは縮小）
- YouTubeのチャット欄を閉じてもコメントが流れ続ける（見えないチャットフレームが代わりに読み込み、アーカイブにも対応）
- コメント付きピクチャーインピクチャー（ベータ、Document Picture-in-Picture）
- `extension/scoring.js`内のJavaScriptのみのローカルスコアラー
- 設定およびフィルターUI
- ローカルサンドボックスおよびレンダラーのパフォーマンスプローブ
- リリースZIPパッケージング
- セキュリティ/サプライチェーンチェック

ブラウザの抽出とレンダリングが実際のボトルネックであるため、スコアリングは小さくローカルに保たれています。

## 仕組み

拡張機能は YouTube の API を呼びません。YouTube がすでに描画しているチャットを読みます。`extension/content.js` は視聴ページと YouTube のライブチャット iframe で動きます。

1. チャット iframe が YouTube のライブチャットのノードを監視します。
2. 新しいメッセージを DOM から読み、NG リストと照合し、`ScoreInput` に正規化します。
3. `extension/scoring.js`が端末内で採点します。絵文字や短いリアクションは速く、長文は遅く流れ、画面が混んだときは品質スコアの高いコメントが優先されます。採点でコメントが非表示になることはありません。ルールと例は[docs/SCORING.ja.md](docs/SCORING.ja.md)にあります。
4. `buildRenderPlan()`は結果を速い/通常/遅い表示タイミングにマッピングします。
5. バックグラウンドサービスワーカーがチャットフレームからトップビデオフレームにメッセージを中継します。
6. トップフレームはコメントを`stage.html`（プレーヤー上に重ねた拡張のフレーム）へ渡します。ここは拡張自身のプロセスで、YouTubeのメインスレッドの外です。コメント1件が1要素で、Chromeのコンポジターが単独で実行する transform アニメーションで動くため、フレームごとのスクリプトは走りません（`danmaku-dom.js`。根拠となる計測は`docs/PERFORMANCE.ja.md`）。従来の canvas レンダラー（`danmaku.js`）は 設定 → パフォーマンス → 描画方式 で選べます。

拡張機能はリモートコードを取得しません。`web/` のモバイル PWA は、同じチャットを `worker/` の Worker 中継経由で YouTube の InnerTube API をポーリングして取得します。両方の経路と、関係するファイル・関数は [ARCHITECTURE.ja.md](ARCHITECTURE.ja.md) にあります。

## コメントの評価アルゴリズム

コメントは描画前に必ずスコアが付きます。スコアでコメントが消えることはありません。スコアが決めるのは次の3つです。

| スコアが決めること | 使う値 | 画面での効果 |
| --- | --- | --- |
| 流れる速さ | **ティア**（速い / 普通 / 遅い） | 一言リアクションは速く流れ、長い文は読める速さで流れる |
| 文字の大きさ | **強調度（emphasis）** | 中身のあるコメントは少し大きく淡い光つき、中身の薄いコメントは少し小さく |
| 画面が満杯のとき誰が残るか | **優先度（priority）** | 新しいコメントは、自分より優先度の低いコメントがあるときだけそれと入れ替わる |

評価は文字列に対する単純な計算で、ブラウザ内で行います（`extension/scoring.js`）。機械学習は使わず、どこにも送信しません。

### 手順1: 文字列を測る

| 測る値 | 数え方 | 例 |
| --- | --- | --- |
| **重み**（どれだけ内容があるか） | 漢字・かな・ハングルは1文字1、英数字は1文字0.5、空白・記号・絵文字は0 | `nice play` = 4、`おつかれさまです` = 8 |
| **絵文字** | カスタム絵文字（画像）もUnicode絵文字も1個につき1 | `👏👏👏` = 3 |
| **繰り返し** | 直前と同じ文字である割合 | `wwwwww` = 1.0 |
| **多様さ** | 異なる2文字の並びの数 ÷ 文字数 | `えがおえがおえがお` ≈ 0.33 |
| **コピー** | 直近64件のどれかと2文字の並びが80%以上重なれば1、そうでなければ0 | 同じ文面の2件目 |

### 手順2: ティア（速さ）を決める

上から順に調べ、最初に当てはまった規則で決まります。

| # | 規則 | ティア | 例 |
| --- | --- | --- | --- |
| 1 | 絵文字があり、重みが2以下 | 速い | `👏👏👏`、カスタム絵文字の連打 |
| 2 | 重みが4以下 | 速い | `草`、`おお`、`lol`、`nice play` |
| 3 | 4文字以上でほぼ繰り返し（繰り返し ≥ 0.5 または 多様さ ≤ 0.35） | 速い | `wwwwww`、`8888888` |
| 4 | 直前のコメントのコピー | 速い | 皆が貼っている同じ文面 |
| 5 | 重みが24以上 | 遅い | 説明、質問 |
| 6 | それ以外 | 普通 | `おつかれさまです`、`what song is this` |

ティアごとに時間が決まっています。コメントの先頭がプレーヤーを横切るのにかかる時間です（既定は 速い3秒 / 普通4秒 / 遅い5秒 を、スクロール速度の設定で割った値）。同じティアのコメントは長さに関係なく同じ速さで動き、長いコメントはそのぶん長く画面に残ります。

### 手順3: 品質・強調度・優先度

```text
品質     = 0.2 + 0.6 × min(重み / 24, 1) + 0.2 × 多様さ − 0.3 × 繰り返し − 0.3 × コピー     （0〜1に収める）
強調度   = 0.6 × 品質   （遅いティアは + 0.18）
優先度   = 0.55 × 強調度 + 0.30 × 品質 + 役割ボーナス（スーパーチャットは + 0.5）
```

- **品質**は、内容が多く多様なほど上がり、繰り返しとコピーで下がります。
- **強調度**が0.62以上なら12%大きく光つきで、0.18以下なら10%小さく描きます（「スコアで文字サイズを変える」をオフにすると無効）。
- **役割ボーナス**: 配信者 0.40、モデレーター 0.25、メンバー 0.10。
- **優先度**が効くのは同時表示数の上限に達したときだけです。上限未満ならすべてのコメントを表示します。

### 計算例

| コメント | ティア | 品質 | 強調度 | 優先度 | 理由 |
| --- | --- | --- | --- | --- | --- |
| `wwwwwwww` | 速い | 0.03 | 0.02 | 0.02 | 同じ文字の繰り返し。小さく描かれ、最初に席を譲る |
| `👏👏👏` | 速い | 0.20 | 0.12 | 0.13 | 絵文字のみ |
| `草` | 速い | 0.43 | 0.26 | 0.27 | 一言リアクション |
| `nice play` | 速い | 0.50 | 0.30 | 0.32 | 重み4 |
| `what song is this` | 普通 | 0.56 | 0.34 | 0.35 | 重み7 |
| `おつかれさまです` | 普通 | 0.60 | 0.36 | 0.38 | 重み8 |
| モデレーターの `おつかれさまです` | 普通 | 0.60 | 0.36 | 0.63 | 役割ボーナス + 0.25 |
| スーパーチャットの `ありがとう` | 普通 | 0.53 | 0.32 | 0.83 | + 0.5、表示時間は1.3倍 |
| `the audio is delayed by about two seconds after the scene transition` | 遅い | 0.98 | 0.77 | 0.72 | 長くて多様。大きく、光つき、遅く流れる |
| 同じ文面を別の人がもう一度投稿 | 速い | 0.3 下がる | | | コピー |

長さによる速度の変化、レーンの割り当て、実際のチャットでの計測などの詳細は [docs/SCORING.ja.md](docs/SCORING.ja.md) にあります。

## プライバシーとストレージ

拡張機能は、ブラウザ内でローカルにコメントをスコアリング、フィルタリング、レンダリングします。表示、動作、およびパフォーマンス設定は、利用可能な場合、Chrome Syncストレージに保存されるため、Chromeはサインインしたプロファイル間でそれらの設定を同期できます。ブロックされたユーザーとブロックされた単語は、現在のデバイスのローカル拡張ストレージにのみ保存されます。チャットテキスト、著者名、およびブロックリストは開発者に送信されません。

## 要件

- 拡張機能を読み込むためのChromeまたはChromium
- スクリプト用のNode.js 22+およびnpm 10+
- オプション: より高速なローカルスクリプトのためのBun 1.3+

JSツールをインストールします:

```sh
npm install
```

セキュリティゲート、型チェック、ウェブビルド、ユニットスイート、ブラウザe2eスイートを実行します。Chromiumがインストールされている場合、サンドボックスのスモークチェックも実行します:

```sh
npm test
```


Bunの同等コマンド:

```sh

```

レンダラーパフォーマンスプローブ:

```sh

```


## Worker 中継

`worker/`内のCloudflare WorkerはYouTube InnerTubeライブチャットコールを中継します。デフォルトでは、チェックインされたWEBクライアントバージョンを使用しますが、プロダクションではコード変更なしに上書きできます:

```sh
wrangler deploy --var INNERTUBE_CLIENT_VERSION:2.20260705.00.00
```

`GET /health`は有効なデフォルトのInnerTubeクライアントバージョンを返します。`GET /health?deep=1&video=<11-char-id>`は、同じ有効なクライアントバージョンでカナリア`next`プローブを実行します。外部のスケジュールされたモニターやCloudflare Cron Triggerから使用して、視聴者がそれにヒットする前にクライアントバージョンの拒否を検出します。

オプションの中継制御:

- `ALLOWED_ORIGINS=https://your-pwa.example`は他のオリジンからのブラウザ呼び出しを拒否します。
- `RATE_LIMIT_PER_MINUTE=120`は各クライアントIPをWorkerアイソレートごとに制限します。`0`を設定すると無効になります。

## Chromeに読み込む

公開済みのストア版ではなく、現在のソースを動かしたい場合はこの手順を使います。

1. `chrome://extensions`を開きます。
2. 開発者モードを有効にします。
3. `未パッケージの読み込み`をクリックします。
4. `extension`ディレクトリを選択します。
5. ライブチャット付きのYouTubeライブストリームを開きます。

コンテンツスクリプトやマニフェストファイルを変更した後は、`chrome://extensions`で拡張機能を再読み込みし、YouTubeタブを再読み込みします。

期待される動作:

- コメントがビデオ上に弾幕スタイルで表示される
- 短いまたはスパムのメッセージが速く移動する
- 高品質または強調されたメッセージが遅く移動する
- 背面にしていたタブに戻ると、その時点から届くコメントだけが流れる（隠れていた間のコメントは再生されない）
- シークバーエリアのトグルで弾幕を隠したり表示したりできる
- デフォルトのYouTubeチャットの隠す/表示は設定に従う

既知の制限:

- YouTubeのポップアウトチャットはビデオプレーヤーなしで別のタブで実行されるため、この拡張機能は元のビデオタブ上にポップアウトチャットメッセージをレンダリングしません。オーバーレイのためには、視聴ページの通常の埋め込みチャットを使用してください。

## リリースビルド

テスターZIPを作成します:

```sh
npm run release:zip
```

Bunパス:

```sh
bun run release:zip:bun
```

アーティファクトは`.release/`に書き込まれ、Gitによって無視されます。詳細は[docs/RELEASE.ja.md](docs/RELEASE.ja.md)を参照してください。

ストアへのリリースは、バージョンを上げたコミットが`main`に入ると[`.github/workflows/chrome-webstore-release.yml`](.github/workflows/chrome-webstore-release.yml)経由で実行され、その後`vX.Y.Z`タグとGitHub Releaseが作成されます。ストアのリスティングとパブリッシャーの初回設定は完了済みです。ワークフローが必要とする認証情報は[docs/RELEASE.ja.md](docs/RELEASE.ja.md)にあります。

パッケージとマニフェストのバージョンを一緒に設定します:

```sh
npm run version:set -- 0.1.1
```

これにより、ルート、`web/`、`worker/`、それらのロックファイルのルートメタデータ、および`extension/manifest.json`が更新されます。
