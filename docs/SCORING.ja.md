# コメントの採点

チャットのコメントは、描画される前に採点されます。採点で決まるのは次の2つです。

- **流れる速さ**（速い・普通・遅いの3段）
- **画面が混んだときにどのコメントを優先するか**（優先度）

採点は端末内の `extension/scoring.js` で行います（`web/scoring.js` は同じファイルです）。採点でコメントを非表示にすることはありません。非表示にするのは NG ワード、種類別の表示設定、そして画面が混んだときの優先度ルール（3章）だけです。

## 1. 何を測るか

画面に実際に見えているものを測ります。

| 項目 | 数え方 | 例 |
| --- | --- | --- |
| 絵文字 | カスタム絵文字の画像も Unicode の絵文字も、1個につき1。画像の alt テキストは絵文字の「名前」なので読みません。 | カスタム絵文字3個 = 3 |
| 重み（どれだけ内容があるか） | 漢字・かな・ハングルは1文字1、英字・数字は1文字0.5。空白・記号・絵文字は0。 | `nice play` = 4、`おつかれさまです` = 8 |
| 繰り返し | 直前と同じ文字が続く割合 | `wwwwww` = 1.0 |
| 多様さ | 異なる2文字組の数 ÷ 文字数 | `えがおえがおえがお` ≈ 0.33 |
| コピー | 直近64件のコメントそれぞれとの2文字組の重なり（Jaccard 類似度） | 0.8以上でコピー |

## 2. 段（速さ）の決め方

上から順に判定し、最初に当てはまったものに決まります。

| 段 | 条件 | 例 |
| --- | --- | --- |
| 速い | 絵文字があり、重みが2以下 | `👏👏👏`、カスタム絵文字の連続、`かわいい`＋絵文字 |
| 速い | 重みが4以下 | `草`、`おお`、`いいね`、`lol`、`nice play` |
| 速い | 4文字以上で、繰り返し0.5以上または多様さ0.35以下 | `wwwwww`、`8888888`、`草草草草草` |
| 速い | 直前に投稿されたコメントのコピー | 同じ文の2回目以降 |
| 遅い | 重みが24以上（日本語なら約24文字、英語なら約48文字） | 長い説明や質問 |
| 普通 | それ以外 | `おつかれさまです`、`what song is this` |

段が速さを決めます。

- **段の時間**: 設定の「速い段階の表示時間」など、段ごとの表示時間で決めます（初期値は3秒・4秒・5秒を、スクロール速度の%で割った値）。コメントの先頭がプレーヤーを横切る時間です。同じ段のコメントは同じ速さで動くので、長いコメントが短いコメントより速く流れることはありません。長いぶん長く画面に残ります。
- **長さで速度を変える**（初期値オン）: 長いコメントほど時間を延ばし、短いコメントは少し縮めます。「長さ速度の強さ」が100%のとき0.8〜1.45倍、初期値の35%では約0.93〜1.16倍です。ここでも絵文字は1個1文字で数えます。
- **固定のルール**: スーパーチャットは時間を1.3倍にし、メンバーシップは常に速い段の時間です。
- **レーン**: 前のコメントが画面から出る前に追いついてしまうレーンには入れません。そのため、速いコメントが遅いコメントにぶつかって重なることはありません。

## 3. 品質と優先度

```text
品質(quality)    = 0.2 + 0.6 × min(重み / 24, 1) + 0.2 × 多様さ − 0.3 × 繰り返し − 0.3 × コピー   （0〜1に収める）
強調(emphasis)   = 0.6 × 品質（遅い段は +0.18）
優先度(priority) = 0.55 × 強調 + 0.30 × 品質 + 役割ボーナス + スーパーチャットなら 0.5
```

- **役割ボーナス**: 配信者 0.40、モデレーター 0.25、メンバー 0.10。
- **強調**: 0.62以上は少し大きく、ふんわり光らせて描きます。0.18以下は少し小さく描きます（「スコアで文字サイズを変える」）。
- **画面が混んだとき**: 同時表示数の上限に達すると、新しいコメントは、画面上で一番優先度の低いコメントより優先度が高い場合にだけ入れ替わります。そうでなければ表示されず、「dropped」として数えられます。採点がコメントを画面に出さない原因になるのはここだけで、それも混雑時だけです。

## 4. 実際のチャットでの計測

4つのライブ配信の481件（2026-10-03）、初期設定、プレーヤー幅1280px。「修正前」は v0.3.2 です。

| | 修正前 | 修正後 |
| --- | --- | --- |
| 絵文字3個以上の連続（51件） | 普通の段、432 px/s | 速い段、553 px/s |
| 採点で非表示になったコメント | 13件（`おお`、`いいね`、`👏👏👏` など） | 0件 |
| 速さの中央値 速い／普通／遅い | 606／478／464 px/s | 553／408／284 px/s |
| 届いた順番で段が変わるか | 変わる（ハッシュによるランダムな揺れ） | コピーのときだけ |

修正前は、カスタム絵文字を名前（`スバルさいなりうむあひる`、12文字）で数えていたため、絵文字の連続が長文扱いになっていました。また、遅い段の長いコメントは普通の段とほとんど同じ速さで流れていました。段の時間がコメント全体の幅を通り過ぎる時間だったためです。「新規性」の判定は、似た文でもまったく違う値になるハッシュを比べていたため、普通のコメントの一部がランダムに重複扱いされていました。

## 5. しないこと

- 機械学習もネットワーク通信も使いません。`toxicity` は常に0です。
- 内容による非表示はしません。それは NG ワードやフィルターで行います。

## コードの場所

- 採点: `extension/scoring.js`（`createFallbackScorer`、`buildRenderPlan`、`measureComment`）
- 採点の呼び出し: `extension/content.js` の `processChatNode`（チャットのフレーム内）
- 時間・レーン・優先度: `extension/danmaku.js` の `_prepare`、`_admit`、`_laneReadyAt`、`_priority`
- テスト: `extension/test/scoring.mjs`、`web/test/danmaku.mjs`
- データの形: [CONTRACT.ja.md](CONTRACT.ja.md)
